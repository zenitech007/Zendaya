🔧 Plumbing decision (I'll bake into the design)

Push everything via WS

  • Single connection, low latency
  • Amplitude/visemes need 20–30 Hz anyway
  • Frontend just listens — clean

Keep HTTP polling

  • Simpler backend (already there)
  • 5+ different rates = 5+ poll loops, lots of fetch overhead
  • Latency = poll interval, not real-time

Recommendation: push via WS. Add a small backend tick (amplitude/visemes at 30 Hz, telemetry at 2 Hz, body+perception on-change). Frontend's existing reconnect handles drops.
